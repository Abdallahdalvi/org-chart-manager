# Ubiqedge People & Structure

A private, database-backed organizational chart workspace. Supplied CSVs are normalized into the initial source document; the originals are not modified.

**Deploy from GitHub:** follow [GITHUB-TO-CASAOS.md](GITHUB-TO-CASAOS.md) for the first installation, private-repository access, Supabase setup and later updates. The guide also explains who approves and why business approvers do not need database-admin rights.

**Current CasaOS login setup:** [CLOUDFLARE-ACCESS.md](CLOUDFLARE-ACCESS.md) configures Cloudflare-only sign-in at `orgchart.dalvi.cloud` with server-enforced editor, HR, assigned-approver and viewer permissions. No new SQL migration or database-admin accounts are required. The old password remains active until `APP_AUTH_MODE=cloudflare` is deliberately configured with the correct team hostname/AUD.

## Using the tool

1. In Cloudflare mode, sign in with your permitted work email; the top bar shows your verified identity and role, and edits are automatically attributed to that email. Local/legacy password mode still uses a manually entered name.
2. The current starting hierarchy is Company Board → CEO → CTO, COO and CSO, with the other existing reporting lines preserved. The Board is a governing body, not an employee. Three source records still need Data review (the Active/Intern records on the inactive tab and the incomplete Ashish record).
3. Use **Import sheets** to select one or more CSV/XLSX files or workbook tabs together, including Active Emp, Inactive Emp, and Departments for oct changes. Preview all changes before one save. Employee IDs are stable keys; duplicate IDs across selected sheets are blocked. Absent rows are retained. Conflicting inactive-sheet statuses go to review. Department definitions can be saved as proposals (default) or current function descriptions, without moving employees or changing managers.
4. Click any employee to edit, add a joiner manually, change direct/functional managers, or mark an exit after reassigning active reports. Cycles and duplicate IDs are blocked.
5. Choose **Vertical** for a traditional top-down branching tree, **Vertical 2** for paired, stacked reports alongside central branches, or **Horizontal** for left-to-right reporting. In Vertical 2, all CEO direct reports share one horizontal row; their teams stack below. Within each team, reports without subteams appear first and expandable managers share the final row, so subteams open below the list. Expanding an individual card preserves zoom and keeps that card in view without reordering it. Cards with active direct reports have a light department-colored fill, even when the team is collapsed or filtered out; cards without direct reports remain white. All cards use distinct department-colored borders/accent strips, with large dark text. Cross-functional relationships are written on cards, without connector lines. Expand/collapse teams, search or filter departments, zoom, and scroll in both directions. Search retains managers for context. Exports include the complete organization, not only the visible/filter-matched cards.
6. In **Departments**, edit function descriptions directly in the current-departments table. October functions remain separate proposals; employee assignments are never guessed. In **Document control**, use **Reset to V1.0** when starting a new controlled register. The register is a spreadsheet-style table: V1.0 begins at the top, later revisions continue downward, and ten blank rows are kept ready below the saved rows. Use **Add version update** for the next revision, or update an existing row and save it with a change note. Both Editor and Full access can set versions. The chart, export headers, default filenames, document-control table and change log use the same current version. Register values are editable document metadata, not authenticated signatures.
7. **Export chart** lets you name the file, select the chart direction and PDF sections, then **Choose PDF pages** lists the actual generated pages. Untick any pages you do not want and download. **Other formats** offers Word, PowerPoint, Excel, SVG and JSON using the same file name.
8. Approval-status banners and the review/approval screen are currently hidden. Existing evidence, server-side role checks and historical snapshots are retained, not deleted. Editor and Full access accounts can edit the chart and its document/department tables; viewer and approval-only accounts remain read-only here. Editing a report field never grants approval permission or changes verified evidence.

## Persistence and access

For your own Supabase/CasaOS deployment, use [CLOUDFLARE-ACCESS.md](CLOUDFLARE-ACCESS.md) for the current login/roles setup or [SELF-HOSTING.md](SELF-HOSTING.md) for legacy password mode. The existing `npm run dev` preview continues to use its local D1 database and preserves your edits. The standalone `build:selfhost`/`start:selfhost` path uses Supabase and does not require Sites. Cloudflare mode validates Access JWTs server-side and never accepts the old app password as a fallback. Live CasaOS/Cloudflare activation is separate from building the source.

The selected backend (local/Sites D1 or self-hosted Supabase) is authoritative; browser storage contains only the editor-name preference. Every confirmed change uses a compare-and-swap revision check and saves a database snapshot. Multiple tabs cannot silently overwrite one another. Download a master backup for independent recovery and handover. The review date tracks the monthly due date but does not send reminders.

Manual versioning does not disable history: separate recovery snapshots and change-log entries are kept even when several saves use the same version label. Every content save gets a new server-generated identity; past approvals cannot apply to a new edit or restored chart just because its version label is reused. Legacy backups remain readable. Version settings and content identities are stored in the existing document JSON, so no Supabase SQL migration is needed.

The old Sites deployment/local preview and explicit basic-password mode retain legacy full editing access and self-reported evidence; the new Cloudflare role enforcement applies only to the standalone CasaOS deployment. Do not publish or share the old preview as a role-restricted app. Backups from another source are historical references, not newly authenticated confirmations. Exact role email lists stay on the server and cannot be edited through a chart upload or the HR reviewer list.

## Export behavior

- PDF: selectable vector chart, individual leadership branches, document control, current functions, employee register, change log and data review. Default: full chart + document control + functions. Select exact generated pages before downloading. Tables use dark text and 13 pt body type. Use digital zoom or poster printing for the large-format chart; PDF tables are static snapshots, editable in the app or the Word/Excel versions.
- Word: executive overview and compact, linked team diagrams, plus native editable reporting, function and document-control tables. The diagram itself is not a Word-native shape group.
- PowerPoint: editable full overview and compact team-detail slides, plus native editable document-control, function and history tables.
- Excel: employee data plus instructions, control, history, approval evidence, required approvers, functions, and October proposals. Re-import the Employees sheet for data changes. Full master restore uses JSON.
- SVG: vector chart only.
- JSON: complete current master, historical evidence references and change log. Separate older saved snapshots can be downloaded from Change log.

## Development and verification

Run `npm install`, then `npm run db:local` once and `npm run dev`. Build with `npm run build`. The local database configuration uses the same logical binding as the Sites scaffold. Hosted migrations are generated by Drizzle and packaged with the Sites hosting helper.

Run `npm test` (no development server needed). Tests cover source counts, name resolution, import merges, row omissions, forward references, duplicate/cyclic reporting, source-status conflicts, approval gating and invalidation, nonoverlapping chart geometry, XLSX round-trip, PDF/DOCX/PPTX output structure, optimistic concurrency, and cross-origin write rejection. `npm run test:exports` covers all chart directions, filenames, editable report fields, role boundaries, PDF section/page selection and long-table pagination. `npm run test:versioning` covers manual/automatic versions, repeated saves, reloads, validation, role boundaries, same-version approval invalidation and exports. The original-source tests expect the supplied CSVs in the local Downloads directory.

For CasaOS, run `npm run build:selfhost`, `npm run test:selfhost`, and `npm run test:access`. The latter verifies cryptographic login checks, email roles, impersonation prevention, approval sequencing, protected endpoints, UI permissions and restore safety without touching a live Cloudflare account or database.

An isolated browser preview was checked for layout switching, search, expansion, inline department editing, document-control saves, file naming and downloading a selected PDF page. Test edits did not reach the live database. The optional WebMCP tools are feature-detected; their actions are read-summary and open-editor only, and neither saves data.

This display/export update requires no Supabase SQL migration or changes to Cloudflare email-role configuration. Optional report fields and Board governance are stored in the existing document JSON; older backups without them remain valid. Existing saved databases are not silently rewritten during deployment: open **Document control → Edit leadership**, choose Company Board and the CEO, confirm the preselected CTO/COO/CSO, then **Save leadership** once. Only selected executive reporting lines change; unrelated employees are preserved. This creates a normal audited revision and retains the previous snapshot.

Every PDF chart page (including selected branch pages) contains the department color legend: blue = Management, purple = Software, orange = Product & Solution, green = Founder Office, red = Admin, cyan = Support, pink = Sales & Marketing, gold = Store. The Board uses a neutral grey accent and is labeled as a governing body, not a department or employee. Additional departments receive additional accent colors. Colors do not represent seniority or role. The same department keeps the same color across all three layouts and filtered/branch views. All connectors show direct reporting only; cross-functional relationships are text notes. JSON is the complete editable master, including Board setup; Excel's employee register does not create a fake Board employee.

Limits: CSV/XLSX up to 5 MB, 500 employees, and 1.5 MB per master save. XLS must first be saved as XLSX. Approval archive stores references, not attachment bytes. Exported documents and backups contain personal information; distribute them through approved internal channels.
